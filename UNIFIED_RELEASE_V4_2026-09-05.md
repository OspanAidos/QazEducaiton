# QazEducation — единый релиз v4

Дата подготовки: 5 сентября 2026 года.

Это единая версия проекта, в которой объединены работающая интеграция amoCRM,
каталожная оплата ApiPay/Kaspi QR, конкурсная логика и серверные сертификаты.
Сайт и рабочий Supabase не меняются автоматически при распаковке архива.

## Что уже проверено до установки

- amoCRM: автоматическая очередь раз в минуту, одна заявка — одна сделка по UUID;
- повторная синхронизация обновляет существующую сделку и не создаёт дубль;
- 3 000 ₸ передаётся товаром ApiPay `626307`, 10 000 ₸ — товаром `626309`;
- квоты: 10 грантов, 30 стипендий и отдельный Top-30;
- четыре серверных шаблона сертификатов формируются в PNG 3508×2480 и PDF A4 landscape;
- QR каждого сертификата ведёт на публичную проверку по уникальному токену;
- подпись и печать не входят в браузерную сборку и читаются только серверной функцией.

Реальная контрольная оплата 10 000 ₸ пока не завершена. Поэтому цепочка
`оплата → webhook → paid → автоматическая подача → сертификат участника`
должна быть проверена отдельно перед финальной публикацией.

## Правила выдачи сертификатов

| Сертификат | Когда создаётся |
|---|---|
| Участника | После реального подтверждённого и не возвращённого платежа 10 000 ₸ и успешной подачи заявки |
| Победителя гранта | После публикации решения `grant` |
| Стипендиата | После публикации решения `scholarship`; на сертификате указано 50 000 ₸ без срока выплаты |
| Финалиста Top-30 | После публикации решения `top30` |

Платёж 3 000 ₸ только за профориентацию не выдаёт сертификат участника.
Повторный запуск выдачи идемпотентен: для одной заявки не создаётся второй
действующий сертификат того же типа.

## Порядок установки — выполнять только после отдельного согласования

### 1. Подготовить новую папку

Не накладывайте релиз частями на старую папку. Распакуйте архив в отдельный
каталог и перенесите в него действующий `.env.local` вручную. Не присылайте
содержимое `.env.local` в чат.

```bash
cd ~/Downloads/QazEducation-unified-certificates-v4-2026-09-05
npm ci
```

### 2. Создать серверный реестр и закрытый bucket

В Supabase SQL Editor проекта `fdoduxdwkgnldrzzxovu` выполните целиком:

```text
supabase/certificates-server-v2.sql
```

Ожидаемый результат: `Success. No rows returned`.

Миграция не удаляет существующие заявки, платежи, результаты или связи amoCRM.

### 3. Загрузить закрытые ресурсы

В Supabase откройте Storage → `qazeducation-certificates-private`. Убедитесь,
что bucket помечен как **Private**. Создайте папку `assets` и загрузите в неё
пять файлов из `private-install-assets/certificates/`:

```text
logo-mark.png
signature-seal.png
DejaVuSans.ttf
DejaVuSans-Bold.ttf
DejaVuSerif.ttf
```

Не загружайте эту папку на сайт. Контрольные SHA-256 находятся рядом в
`SHA256SUMS.txt`.

### 4. Задать адрес QR-проверки

Из корня новой папки:

```bash
npx supabase secrets set \
  CERTIFICATE_VERIFY_BASE_URL=https://qazeducation.kz/certificate \
  --project-ref fdoduxdwkgnldrzzxovu
```

### 5. Развернуть две функции

```bash
npx supabase functions deploy certificate-file \
  --project-ref fdoduxdwkgnldrzzxovu \
  --use-api
```

```bash
npx supabase functions deploy telegram-notify \
  --project-ref fdoduxdwkgnldrzzxovu \
  --use-api
```

Не используйте `--no-verify-jwt` для `certificate-file`.

Повторно разворачивать `amocrm-sync`, `apipay-invoice` и `apipay-webhook` для
сертификатов не требуется, если в рабочем Supabase уже стоят проверенные версии.

### 6. Проверить локально до публикации

```bash
npm run build
npm run dev
```

Проверить:

1. вход участника и администратора;
2. amoCRM показывает активную фоновую задачу и 0 ошибок;
3. в админ-панели указано 30 стипендий;
4. публичный маршрут `/certificate/<token>` открывается;
5. владелец сертификата скачивает PNG и PDF, другой участник — нет;
6. подпись перекрывает печать, имя/номер/дата/QR читаются;
7. повторная выдача не увеличивает число действующих сертификатов.

### 7. Настроить основание итоговых сертификатов

В админ-панели, в разделе результатов, заполнить документ, номер и дату
протокола. Если номер или дата не заполнены, система использует формулировку
«Решение конкурсной комиссии» и дату публикации.

Кнопку «Выдать недостающие сертификаты» использовать после проверки одного
документа. Повторное нажатие безопасно и не создаёт дубли.

### 8. Контрольная проверка перед публикацией

После разрешения руководителя провести одну реальную оплату 10 000 ₸ и
проверить всю цепочку:

1. ApiPay присвоил счёту статус оплаты;
2. в Supabase платёж стал `paid`;
3. заявка подалась автоматически;
4. в amoCRM обновилась та же сделка;
5. участнику выдан один сертификат участника;
6. PDF и PNG скачиваются, QR подтверждает сертификат;
7. Telegram-сообщение доставлено.

Только после этого собирать production `dist` и публиковать сайт.

## Откат

До публикации сохранить резервную копию текущего сайта и базы. При проблеме
не удаляйте таблицу `certificates`: она является реестром уже выданных номеров.
Можно временно не публиковать новый `dist` и не использовать выдачу, сохранив
записи для диагностики.
