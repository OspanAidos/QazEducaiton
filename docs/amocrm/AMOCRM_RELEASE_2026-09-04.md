# Подключение QazEducation к amoCRM без дублей

Эта версия использует долгосрочный токен amoCRM и связывает одну строку
`applications.id` ровно с одной сделкой `amo_lead_id`.

## Что происходит

1. После завершения регистрации создаётся одна сделка в воронке `QAZEDUCATION`.
2. Заполнение анкеты, выбор пакета, оплата, подача и решение комиссии обновляют
   ту же сделку.
3. Триггеры Supabase объединяют повторные события в одну работу на заявку.
4. Перед созданием сервер ищет сделку по полю `QazEducation: UUID заявки`.
5. Параллельная обработка блокируется арендой на уровне PostgreSQL.
6. Если соединение оборвалось в момент создания, новая сделка не создаётся
   повторно в течение защитного интервала: сначала сервер восстанавливает ID.

## Какие значения нужны

| Значение | Где используется | Что указать |
|---|---|---|
| Redirect URI | Только в форме интеграции amoCRM | `https://qazeducation.kz` |
| `AMO_BASE_URL` | Supabase Edge Function Secret | `https://lawacademy.amocrm.ru` |
| `AMO_LONG_LIVED_TOKEN` | Supabase Edge Function Secret | долгосрочный токен из amoCRM |
| `AMO_SYNC_ENABLED` | Supabase Edge Function Secret | сначала `false` |
| `SITE_ORIGIN` | Необязательный Supabase Secret | `https://qazeducation.kz` |

`AMO_REDIRECT_URI`, `AMO_CLIENT_ID` и `AMO_CLIENT_SECRET` для этой реализации
в Supabase не нужны. Redirect URI нужен amoCRM при создании интеграции, даже
если авторизация выполняется долгосрочным токеном.

## Где взять долгосрочный токен

1. В amoCRM откройте **Настройки → Интеграции → Созданные интеграции**.
2. Создайте внешнюю интеграцию `QazEducation Site` или откройте уже созданную.
3. В поле ссылки перенаправления укажите `https://qazeducation.kz`.
4. Дайте права на сделки, контакты и списки/поля.
5. В разделе **Ключи и доступы** нажмите создание долгосрочного токена.
6. Скопируйте токен сразу. Не отправляйте его в чат и не сохраняйте в проект.

Если пункта долгосрочного токена нет, проверьте, что интеграция внешняя и
создана в этом аккаунте пользователем с административными правами.

## Где создать секреты

Рекомендуется не создавать `.env` с настоящим токеном. Откройте:

**Supabase Dashboard → project `fdoduxdwkgnldrzzxovu` → Edge Functions → Secrets**

Добавьте три обязательных секрета `AMO_BASE_URL`, `AMO_LONG_LIVED_TOKEN` и
`AMO_SYNC_ENABLED`. `SITE_ORIGIN` можно не добавлять: в коде уже установлен
`https://qazeducation.kz`. Образец без настоящего токена лежит в
`supabase/amocrm-secrets.example`.

## Порядок установки

До пункта 7 сделки amoCRM не создаются.

1. Сделайте резервную копию Supabase.
2. В SQL Editor выполните целиком `supabase/amocrm-integration-v2.sql`.
3. Создайте секреты, оставив `AMO_SYNC_ENABLED=false`.
4. Из корня этого проекта разверните функцию:

   ```bash
   npx supabase functions deploy amocrm-sync \
     --project-ref fdoduxdwkgnldrzzxovu \
     --use-api
   ```

   Флаг `--no-verify-jwt` не использовать.

5. Соберите и опубликуйте сайт обычным способом. В админ-панели появится блок
   **amoCRM · QAZEDUCATION**.
6. Нажмите **Проверить подключение**, затем **Подготовить поля**. Это создаёт
   только служебные поля, но не сделки. Проверьте и сохраните сопоставление всех
   этапов. Для этапа без соответствия можно выбрать «Не менять этап».
7. После проверки измените секрет `AMO_SYNC_ENABLED` на `true`.
8. Зарегистрируйте один тестовый аккаунт. В amoCRM должна появиться одна сделка.
9. Измените заявку два-три раза и нажмите в админ-панели
   **Синхронизировать очередь**. Количество сделок не должно увеличиться; поля и
   этап существующей сделки должны обновиться.
10. Только после теста обработайте очередь существующих заявок партиями по 25.

## Контроль дублей

В Supabase можно проверить связь:

```sql
select
  a.number,
  j.amo_lead_id,
  j.state,
  j.desired_revision,
  j.processed_revision,
  j.last_error,
  j.last_synced_at
from public.crm_sync_jobs j
join public.applications a on a.id = j.application_id
order by j.updated_at desc;
```

У одной заявки всегда одна строка и один `amo_lead_id`. Если в amoCRM уже были
созданы дубли старым кодом, новая функция не удаляет их автоматически. При
обнаружении нескольких карточек с одинаковым UUID она остановит синхронизацию
с ошибкой `DUPLICATE_AMO_LEADS`, чтобы администратор объединил карточки вручную.

## Секреты и безопасность

- Функция защищена JWT Supabase.
- Проверка соединения, создание полей, сопоставление этапов и массовая очередь
  доступны только пользователю из `admin_users`.
- Пользователь может синхронизировать только собственную заявку.
- Долгосрочный токен никогда не возвращается браузеру.
- `AMO_SYNC_ENABLED=false` блокирует создание и обновление сделок, но разрешает
  администратору проверить соединение и подготовить поля.

## Что не разворачивать

Не разворачивайте `amocrm-auth` и не используйте OAuth-таблицы из архива Клода.
В этой версии нужна только функция `amocrm-sync` и SQL-файл версии v2.

Официальная документация: [долгосрочный токен](https://www.amocrm.ru/developers/content/oauth/step-by-step),
[API сделок](https://www.amocrm.ru/developers/content/crm_platform/leads-api),
[воронки и этапы](https://www.amocrm.ru/developers/content/crm_platform/leads_pipelines).
