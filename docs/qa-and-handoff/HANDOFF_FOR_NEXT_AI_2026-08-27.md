## 3. Что реализовано в этой версии

### Регистрация и вход

- Участники регистрируются и входят через `@QazEducationBot`.
- При регистрации сайт обязательно спрашивает настоящее имя и фамилию.
- Telegram username, first name и last name не подставляются вместо ФИО.
- Имя и фамилия валидируются и сохраняются серверной функцией
  `complete_participant_registration`.
- Администратор и комиссия входят через отдельный служебный блок email + пароль
  на `/login`.
- Роли определяются таблицами `admin_users` и `commission_members`.
- Действующие пароли в Supabase посмотреть нельзя; при необходимости их можно
  только сбросить. Не удалять служебные аккаунты без необходимости: их UUID
  связаны с ролями.

### Заявки и оплата

- Черновик сохраняется автоматически.
- Неоплаченная заявка не считается поданной.
- Финальная отправка выполняется через серверную функцию
  `submit_own_application`.
- Сервер проверяет обязательные поля, возраст, категорию, гражданство, согласия,
  документы, вид поддержки, запрещённые специальности и оплату.
- Повторная отправка из `needs_fixes` не требует повторной оплаты.
- Пользователь и веб-администратор не могут самостоятельно выставить `paid`.
- Оплата считается подтверждённой только после серверного статуса `paid`.
- `qr_scanned` — промежуточный статус и не считается оплатой.
- Вместо выставления счёта реализован динамический Kaspi QR через ApiPay.kz.
- Для конкурса QR создаётся на 10 000 ₸, для подбора вуза — на 3 000 ₸.

### Админ-панель

Очереди:

1. «Поданные».
2. «Черновики».
3. «Ожидают оплату».
4. «На доработке».
5. «Переданы комиссии».
6. «Апелляции».
7. «Отклонённые».
8. «Завершённые».
9. «Все записи».

Реализованы:

- поиск и фильтры по статусу, оплате, категории, поддержке и датам;
- карточка с номером, ФИО, статусом, оплатой, прогрессом и датами;
- человеческие подписи вместо технических полей;
- проверка комплектности и серверных согласий;
- проверка документов: принять / потребовать замену / комментарий;
- блок платежа и история изменения статуса;
- история действий администратора;
- комментарии комиссии и средний балл активных членов комиссии;
- Excel-выгрузка с русскими названиями полей;
- действия «Передать комиссии», «Отправить на доработку», «Отклонить»;
- обязательный комментарий для доработки и отклонения;
- серверная блокировка передачи комиссии без оплаты, согласий и принятых
  документов.

### Комиссия и результаты

- Комиссия видит мотивацию, достижения и успеваемость.
- Комиссия не видит удостоверение личности, свидетельство о рождении, документ
  и согласие законного представителя.
- Баллы валидируются сервером и в интерфейсе.
- Грант: 25 / 30 / 20 / 10 / 15.
- Стипендия: 30 / 20 / 25 / 15 / 10.
- Итог по нескольким активным членам комиссии — среднее значение.
- Квоты публикации: 10 грантов, 30 стипендий, Top-30.

### Внешний вид и контакты

- Сохранена тёмно-зелёная и золотая стилистика.
- Декоративные мелкие подписи над основными заголовками удалены по сайту.
- «Горячая линия» удалена из футера.
- WhatsApp: `+7 775 080 8051`, `https://wa.me/77750808051`.
- Техподдержка остаётся отдельным номером: `+7 775 080 8041`.
- RU/KZ версии сохранены.
- Текущий код использует Unbounded для display-текста и Golos Text для
  основного текста. Не менять типографику и визуальную систему без запроса.

## 4. Импорт 48 записей старого сайта

Исходник пользователя: `qaz-clients-2026-08-20.xlsx`.

Готовая миграция: `supabase/legacy-applications-v1.sql`.

Миграция:

- создаёт защищённую таблицу `legacy_applications`;
- импортирует `OLD-2026-0001` — `OLD-2026-0048`;
- сохраняет 46 записей как `draft`;
- сохраняет 2 записи как `awaiting_payment`;
- не создаёт фиктивные аккаунты;
- не создаёт фиктивные или подтверждённые платежи;
- сохраняет старый статус «Оценена» только в истории источника;
- связывает найденные аккаунты по нормализованному телефону или email;
- автоматически связывает оставшиеся записи после будущей регистрации;
- использует уникальный `source_key` и `ON CONFLICT`, поэтому повторный запуск
  не создаёт дубликаты.

На момент передачи миграция ещё не применена. После её запуска проверить:

```sql
select mapped_status, count(*)
from public.legacy_applications
group by mapped_status
order by mapped_status;
```

Ожидается:

```text
awaiting_payment — 2
draft — 46
```

Затем обновить `/admin` через `Command + Shift + R` и проверить номера
`OLD-2026-0001` — `OLD-2026-0048`.

## 6. `.env.local` и Supabase

Файл должен называться именно `.env.local` и лежать рядом с `package.json`.
На macOS его проще создавать через Terminal, поскольку Finder может не дать
начать имя файла с точки.

```env
VITE_SUPABASE_URL=https://fdoduxdwkgnldrzzxovu.supabase.co
VITE_SUPABASE_PUBLISHABLE_KEY=<publishable key из того же проекта>
```

Название второй переменной строго в единственном числе:
`VITE_SUPABASE_PUBLISHABLE_KEY`. Не использовать клиентскую переменную
`SUPABASE_PUBLISHABLE_KEYS`.

В `.env.local` запрещено помещать:

- `service_role`;
- `sb_secret_...`;
- пароль базы;
- Telegram Bot Token;
- API-ключ ApiPay;
- секрет вебхука.

Publishable key не записан в этот файл передачи. Не просить пользователя
отправлять пароли или секретные ключи в чат.

После любого изменения `.env.local` обязательно остановить Vite через
`Control + C` и запустить снова.

## 9. ApiPay и Kaspi QR

Клиентский интерфейс уже реализован, но реальная оплата не заработает без
настройки ApiPay и публикации функций.

Секреты хранятся только в Supabase Edge Functions Secrets:

```text
APIPAY_API_KEY=<секрет>
APIPAY_WEBHOOK_SECRET=<секрет подписи>
APIPAY_BASE_URL=https://api.apipay.kz/api/v1
```

Публикация:

```bash
npx supabase functions deploy apipay-invoice
npx supabase functions deploy apipay-webhook
```

Вебхук:

```text
https://fdoduxdwkgnldrzzxovu.supabase.co/functions/v1/apipay-webhook
```

В ApiPay включить события изменения счёта. Вебхук проверяет HMAC-подпись.
Подтверждение участником, скриншот или ручной статус со стороны браузера не
считаются оплатой.

## 11. Публикация на действующий сервер

Сначала SQL и Edge Functions, затем новая сборка сайта.

Критически важно: `dist` нужно пересобрать после создания правильного
`.env.local`. Сборка, созданная без переменных Vite, откроет публичные страницы,
но авторизация и Supabase не заработают.

```bash
npm run build
tar -czf ~/Desktop/qazeducation-dist-2026-08-27.tar.gz -C dist .
scp ~/Desktop/qazeducation-dist-2026-08-27.tar.gz root@77.67.8.204:/tmp/
ssh root@77.67.8.204
```

Перед заменой:

1. определить точный `root` сайта через `nginx -T`;
2. сделать резервную копию текущего каталога сайта;
3. распаковать релиз во временную папку;
4. проверить наличие `index.html`;
5. скопировать только содержимое `dist`;
6. выполнить `nginx -t`;
7. проверить домен и маршруты.

Не загружать в публичный каталог сервера:

- `.env.local`;
- `src`;
- `supabase`;
- `node_modules`;
- любые серверные секреты.

Домен, DNS и SSL повторно настраивать не требуется.
