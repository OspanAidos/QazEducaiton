# QazEducation — установка модуля итогов конкурса v1

Этот патч рассчитан на текущую рабочую версию проекта с Telegram-авторизацией и очередью Telegram-уведомлений.

## Что добавлено

- раздел «Итоги конкурса · 2026» в админ-панели;
- завершение и повторное открытие приёма заявок;
- серверный предварительный рейтинг;
- 10 образовательных грантов;
- 30 стипендий;
- единый Top-30 резервного списка среди оставшихся участников;
- итог «не прошёл конкурс» для остальных оценённых заявок;
- финальное уведомление ранее отклонённым участникам;
- публикация итогов одной серверной транзакцией;
- публичная страница результатов только с номерами заявок;
- трёхдневное окно процедурных апелляций и финализация после их рассмотрения;
- автоматическая Telegram-рассылка партиями;
- контроль `Отправлено / Ожидает / Ошибка`;
- кнопки «Продолжить рассылку» и «Повторить ошибки»;
- контролируемый повторный расчёт только после окончания срока и закрытия всех апелляций;
- блокировка публикации, если есть незавершённые заявки, неполные оценки комиссии или равенство баллов на границе квоты;
- кнопка «Выйти» в админке и панели комиссии перенесена в шапку, как у участника; плавающая кнопка внутри служебных панелей убрана.

## Установка

### 1. Скопировать файлы

Распакуйте ZIP в корень проекта `qazeducation` с заменой файлов.

### 2. SQL

В Supabase → SQL Editor выполните:

1. `supabase/telegram-notifications.sql` — можно повторно, файл идемпотентный;
2. `supabase/workflow-v5.sql`;
3. `supabase/appeals-v1.sql`;
4. `supabase/competition-results-v1.sql`.

Оба запроса должны завершиться `Success`.

### 3. Edge Function

В PowerShell из корня проекта:

```powershell
npx.cmd supabase functions deploy telegram-notify
```

`--no-verify-jwt` здесь НЕ нужен: функцию вызывают авторизованные участники/администратор.

### 4. Запустить сайт

```powershell
npm run dev
```

## Как работает завершение конкурса

1. Администратор нажимает «Завершить приём заявок».
2. Новая финальная подача заявок блокируется. Повторная отправка после `needs_fixes` остаётся разрешённой до публикации итогов.
3. «Сформировать предварительные итоги» показывает результат без записи решений в заявки.
4. «Опубликовать итоги» доступно только когда:
   - нет заявок в `submitted / tech_review / needs_fixes / accepted`;
   - все заявки комиссии оценены всеми активными экспертами;
   - нет одинакового среднего балла на границе квоты.
5. После подтверждения сервер фиксирует предварительные решения, открывает апелляцию на 3 рабочих дня и создаёт персональные Telegram-уведомления.
6. Рассылка запускается автоматически партиями по 15 сообщений.
7. После срока секретариат рассматривает все апелляции; удовлетворённые заявки возвращаются комиссии.
8. Кнопка «Финализировать после апелляций» повторно рассчитывает рейтинг, но не открывает новый срок обращений.
9. Если браузер закрыт или сеть пропала, сообщения остаются `pending`; рассылку можно продолжить из админки.
10. Ошибки остаются `failed` и повторяются кнопкой «Повторить ошибки».

## Важно про одинаковые баллы

При равенстве итоговых баллов применяется утверждённое правило тай-брейка: для гранта — более высокий средний балл за мотивацию, для стипендии — более высокий средний балл по критерию социальной потребности. Полное равенство на границе квоты блокирует публикацию до решения комиссии.

## Что считать Top-30

В этой версии Top-30 — единый резерв из 30 лучших оставшихся оценённых участников после распределения грантов и стипендий, независимо от выбранного вида поддержки.

## Безопасность

- Telegram Bot Token остаётся только в Supabase Edge Function Secrets;
- публикация выполняется только RPC-функцией администратора;
- повторный расчёт разрешён только после окончания апелляционного срока и закрытия всех обращений;
- плавающая служебная кнопка на обычных публичных страницах сохранена только как быстрый возврат в админку/комиссию.
