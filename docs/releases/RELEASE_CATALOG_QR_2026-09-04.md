# QazEducation — каталожный Kaspi QR, 04.09.2026

Это точечное обновление поверх уже установленного QR-релиза от 03.09.2026.
Оно исправляет ответ ApiPay `422 catalog_requires_cart_items`. Действующий сайт,
Supabase и кабинет ApiPay при подготовке архива не изменялись.

## Согласованный каталог

| Пакет | Сумма | ID товара ApiPay | Состояние |
| --- | ---: | ---: | --- |
| Подбор вуза | 3 000 ₸ | `626307` | Доступен |
| Участие в конкурсе + подбор вуза | 10 000 ₸ | `626309` | Доступен |
| Доплата после подбора вуза | 7 000 ₸ | нет | Временно заблокирована |

Сервер сам выбирает товар по типу пакета. Браузер не может передать свою цену,
ID товара, пользователя или оплаченный статус. Запрос к `/invoices/qr` содержит
`cart_items` с одной единицей утверждённого товара; поле `amount` не отправляется.
Сумма созданного счёта всё равно сверяется с серверной бронью перед показом QR.

Если подбор за 3 000 ₸ уже оплачен, новый конкурсный QR не создаётся. Участник
видит объяснение и предложение обратиться в поддержку. Защита действует и в
интерфейсе, и в SQL-функции, поэтому её нельзя обойти прямым запросом.
Ранее подтверждённые корректные оплаты и доступы не изменяются.

## Что проверить перед обновлением

- резервная копия базы и действующего сайта уже сохранена;
- секреты `APIPAY_API_KEY` и `APIPAY_WEBHOOK_SECRET` остаются только в Supabase;
- пилотный список `APIPAY_CHECKOUT_USER_IDS` не очищается до завершения проверки;
- две неуспешные попытки с кодом 422 имеют статус `cancelled` и не являются оплатой;
- для проверки используется заполненная заявка тестового участника.

## Порядок серверного обновления

1. В Supabase Edge Function Secrets временно установите
   `APIPAY_PAYMENTS_ENABLED=false`. Это запрещает только создание новых счетов;
   webhook продолжает принимать и сверять уведомления по уже созданным счетам.
2. В SQL Editor целиком выполните только `supabase/catalog-qr-v3.sql`.
   Старые SQL-файлы повторно запускать не нужно. Миграция не удаляет и не
   изменяет существующие заявки или платежи.
3. Из корня проекта опубликуйте обновлённую функцию:

   ```bash
   npx supabase functions deploy apipay-invoice \
     --project-ref fdoduxdwkgnldrzzxovu --use-api
   ```

   `apipay-webhook` этим релизом не менялся, повторно публиковать его не требуется.
4. С вашим существующим `.env.local` рядом с `package.json` соберите frontend:

   ```bash
   npm run build
   ```

5. Проверьте локально `/payment` и `/match`. Значения `.env.local`, ключи и SQL
   нельзя копировать в `dist` или публичную папку сайта.
6. Для одного согласованного тестового UUID установите
   `APIPAY_PAYMENTS_ENABLED=true`, не удаляя `APIPAY_CHECKOUT_USER_IDS`.
7. Создайте один реальный QR только для пакета 10 000 ₸ или 3 000 ₸. Возврат
   этим проектом не выполняется, поэтому денежную проверку нужно заранее
   согласовать. Если деньги списаны, второй раз не платите даже при задержке UI.

## Контроль одной реальной оплаты

После оплаты сверьте один и тот же ID счёта, сумму и пакет в ApiPay и Supabase.
В таблице `payments` должны быть `provider='apipay'`, `status='paid'`,
`is_sandbox=false`, `refunded_tenge=0`. Для полного пакета заполненная заявка
должна автоматически перейти в `submitted`, а подбор вуза — открыться.

Безопасный запрос для просмотра последних записей тестового участника:

```sql
select created_at, payment_type, amount_tenge, status, provider,
       provider_payment_id, is_sandbox, refunded_tenge
from public.payments
where user_id = '<UUID тестового участника>'::uuid
order by created_at desc
limit 10;
```

Если ApiPay списал деньги, но сайт не подтвердил оплату, не создавайте новый QR
и не меняйте статус вручную. Сохраните ID счёта и проверьте журналы функций.

## Публикация frontend

Только после успешной пилотной оплаты создайте резервную копию каталога сайта и
замените его содержимым новой `dist`. Затем проверьте `/payment`, `/match`, вход,
заявку, админ-панель и мобильное отображение. До общего запуска сохраняйте
непустой `APIPAY_CHECKOUT_USER_IDS`; пустой список откроет создание QR всем
авторизованным участникам.

При любой проблеме снова установите `APIPAY_PAYMENTS_ENABLED=false`. Не удаляйте
платежи и события и не сбрасывайте `pending` вручную.
